# Pit Crew 화면 명세 (SPEC)

기준: 「Pit Crew 기획서 및 MVP 상세 정의서」 v0.2 (2026-11-03), `CLAUDE.md`, `docs/PLAN.md`, `docs/sdk/*.md`
이 문서는 **화면마다 무엇이 보이고, 누르면 어떻게 되고, 언제 끝났다고 보는지**를 정한다. 개발 순서는 `PLAN.md`를 따른다.

## 0. 이 문서를 쓰는 법

- 이 문서가 기획서나 `CLAUDE.md`와 다르면 **작업을 멈추고 먼저 묻는다.**
- **무엇을 보여 주는가**(문구, 체크 항목, 동작)는 이 문서를 따른다. **어떻게 보이는가**(배치, 색, 크기, 간격)는 `docs/design/SC-xxx.png`와 `tokens.md`를 따른다. 디자인 이미지의 문구가 이 문서와 다르면 임의로 고르지 말고 묻는다.
- 문구는 초안이며 경찰청·보험업계·응급 공식 안내와 대조해 확정한다(11/9). 모든 안내에 "참고용"을 표시하고 법률·의료 조언이 아니라고 밝힌다.
- "확인 방법"은 개발 후 에뮬레이터에서 직접 해 보는 절차이며, 모두 통과해야 그 화면이 끝난 것이다.

## 1. 공통 규칙

### 1.1 화면 공통

| 항목 | 규칙 |
|---|---|
| 화면 크기 | 1682×1210px(1px = 1dp). 계기판·하단 공조 바 영역은 그리지 않는다 |
| 상단 바 | 앱 이름, 현재 단계 n/7(사고 모드만), "가상 차량 값" 배지 |
| 하단 바 | [이전] [다음] (사고 모드 화면). 사고 모드 어디서든 [사고 모드 나가기]로 홈에 돌아갈 수 있고, 이때 확인 대화상자를 보여 준다 |
| 입력 | 차량 화면에서 타이핑하지 않는다. 선택 버튼, 체크, 스위치, 음성 버튼만 쓴다 |
| 터치·글자 | 큰 터치 영역, 고대비, 짧은 문구. 본문 28px 이상, 제목 40px 이상, 버튼 높이 96px 이상 |
| 값이 없을 때 | 숨기지 않고 회색 "확인 불가" 배지를 보여 준다. 앱이 종료되지 않는다 |
| 에뮬레이터 | 차량 값은 가상 값이므로 "가상 차량 값" 배지를 표시한다 |
| 금지 | 법적·과실 판단, 사고 자동 감지, 에어백·문 잠김·차대번호·비상등 자동 확인·타이어 값, 차량 제어(set) 호출 |

### 1.2 사고 모드 세션 데이터

사고 모드를 시작하면 세션 하나가 만들어지고, 아래 값을 메모리에 들고 있다가 SC-260 요약과 SC-270 종료에서 쓴다.

| 값 | 설명 |
|---|---|
| 시작 시각 | SC-200에서 [네, 세웠어요]를 누른 시각. 실제 사고 시각과 다를 수 있음 |
| 체크 현황 | SC-210, 230, 240의 항목별 체크 여부. 체크하지 않고 넘어간 항목은 "확인 안 함" |
| 부상 응답 | 없음 / 있음 / 모름 / 응답 안 함 (SC-220) |
| 차량 상태 | 문·창문(영역별), 배터리, 주행 거리, 방향지시등. 각 값은 "값" 또는 "확인 불가", 읽은 시각 포함 |
| 위치·주소·날씨 | SC-205에서 허용했고 읽기에 성공한 경우에만 (Phase 7~8, 11) |
| 음성 메모 | 사용자가 확인하고 저장한 경우에만 (Phase 11) |

- 사고 모드를 끝내면 사용자가 보관을 고르지 않은 한 세션 데이터를 즉시 폐기한다.
- 상대방 정보, 사진, 차대번호는 세션에도 저장에도 전송에도 포함하지 않는다.

### 1.3 사고 모드 흐름

```
SC-100 홈 ─[사고가 났어요]→ (SC-205 최초 1회) → SC-200 → SC-210 → SC-220 ─없어요→ SC-230 → SC-240 → SC-250 → SC-260 → (SC-280, SC-290) → SC-270 → SC-100
                                                              └있어요/모르겠어요→ SC-221 ─[확인했어요]→ SC-230
```

- 진행률: SC-200 1/7, SC-210 2/7, SC-220 3/7(SC-221도 3/7), SC-230 4/7, SC-240 5/7, SC-250 6/7, SC-260 7/7.
- [이전]은 직전 화면으로 돌아간다. SC-230에서 [이전]은 SC-220(부상 확인)으로 간다(SC-221을 거쳐 왔더라도 같다).
- 체크 화면의 [다음]은 항상 눌 수 있다(현장에서 막히지 않게).
- SC-205는 사고 모드 첫 진입 때 한 번만 보여 주고, 이미 정했으면 건너뛴다. SC-280, SC-290은 SC-260 이후에 이어진다. 구현은 Phase 7, 12, 13에서 한다. 그 전에는 흐름에 넣지 않는다.

### 1.4 차량 값 읽기 규칙

| 카드 | 지원 확인 → 읽기 (샘플 앱 로그 기준 이름) | 영역 | 값 해석 |
|---|---|---|---|
| 문 열림 | checkDoorPositionCapabilities → getCurrentDoorPosition | Row 1~3 좌·우, Hood, Rear | 0 닫힘, 0보다 크면 열림(Hood·Rear는 0~100) |
| 창문 | checkWindowPositionCapabilities → getCurrentWindowPosition | capability 응답으로 확인한 영역만 | 0~10, 0 닫힘, 0보다 크면 열림(10 완전 열림) |
| 배터리 | checkEvBatteryStateOfChargeCapabilities → getEvBatteryStateOfCharge | 없음 | 숫자 + %(SDK 문서 기준, 에뮬레이터 값으로 검증하지 않음) |
| 주행 거리 | checkCurrentDistanceDrivenCapabilities → getCurrentDistanceDriven | 없음 | 숫자 + km(SDK 문서 기준, 에뮬레이터 값으로 검증하지 않음) |
| 방향지시등 | checkTurnSignalStateCapabilities → getCurrentTurnSignalState | 없음 | OFF, LEFT 등 |

- 위 이름은 샘플 앱 API 로그에서 확인한 것이다. **실제 Kotlin 시그니처와 권한 이름은 SDK 클래스와 샘플 코드로 확인하고, 추측해서 만들지 않는다.**
- 순서: 지원 확인 → 읽기 → 예외 처리 → 표시. 지원 확인 없이 읽지 않는다. 예외는 모두 잡아 "확인 불가"로 표시한다.
- 영역이 있는 기능은 지원되는 영역만 읽는다. 창문은 Row 1 Left만 확인됐으므로 다른 영역은 capability 응답을 본 뒤에만 쓴다.
- 리스너는 한 번만 등록하고 화면을 떠날 때 해제한다. 읽기 전용이며 set 호출과 CONTROL_* 권한은 쓰지 않는다.
- 배터리·주행 거리는 %, km를 붙여 보여 주되(SDK 문서 기준) 경고 판단은 하지 않는다.

### 1.5 SDK 상태 문구 (SC-000, SC-400 공통)

| 상태 | 문구 |
|---|---|
| 읽기 가능 | 읽을 수 있어요 |
| 미지원 | 이 차량에서는 지원하지 않아요 |
| 확인 실패 | 확인하지 못했어요 |

## 2. 화면별 명세 (P0)

### SC-000 앱 시작·연동 초기화 (Phase 2)

- 목적: 앱을 열 때 Vehicle SDK를 초기화하고 5개 기능의 지원 여부를 한 번에 확인한다.
- 동작
  1. Vehicle SDK 초기화
  2. 문, 창문, 배터리, 주행 거리, 방향지시등의 지원 여부 확인
  3. 결과를 세 상태(1.5)로 보관
  4. 홈(SC-100)으로 이동
- 예외: 초기화가 실패하면 홈으로 이동하되 차량 연동을 끄고 "차량 정보를 읽을 수 없어요. 체크리스트는 그대로 쓸 수 있어요"를 표시한다. 개별 확인이 실패하면 그 기능만 "확인하지 못했어요"로 둔다.
- 확인 방법
  - 정상 실행 시 홈으로 이동한다.
  - 미지원 기능이 있어도 앱이 종료되지 않는다.
  - 앱을 닫을 때 SDK를 해제한다.

### SC-100 홈 (Phase 2)

- 구성(시안 `SC-100.png` 기준): 상단 바(앱 이름, "사고 직후 정차부터 마무리까지 안내", "가상 차량 값" 배지), 연동 상태 한 줄(배지와 문구, 예: "차량 정보 5개 중 5개를 읽을 수 있어요"), 왼쪽에 큰 채운 카드 [사고가 났어요](보조 문구 "7단계로 차근차근 안내해요"), 오른쪽에 같은 크기 카드 3개 [출발 전 점검] [차량 연동 상태] [설정·정보], 하단 안내 "차를 안전하게 세운 뒤에 사용하세요".
- 동작: 각 버튼은 해당 화면으로 이동한다. 주행 중 사용 제한은 플랫폼이 처리하므로 앱에서 별도 차단을 만들지 않는다.
- 연동 상태 줄: 5개 모두 읽히면 정상 배지, 1~4개면 주의 배지, 0개면 회색 "확인 불가" 배지. 문구는 "차량 정보 5개 중 N개를 읽을 수 있어요"(0개는 "확인 불가"). 시안의 "차량 연결됨"은 쓰지 않는다.
- 예외: SC-000 결과가 0개이거나 초기화가 실패하면 연동 상태 줄에 "확인 불가"(회색)와 "차량 정보를 읽을 수 없어요. 체크리스트는 그대로 쓸 수 있어요"를 보여 주고, 사고 모드는 계속 시작할 수 있다.
- 확인 방법
  - 홈에서 [사고가 났어요]까지 터치 한 번으로 간다.
  - 연동 상태 줄 숫자가 SC-000 결과와 같다.
  - 디자인 `SC-100.png`와 배치가 같다.

### SC-200 정차 확인 (Phase 3)

- 문구: "안전한 곳에 차를 세우셨나요?"
- 버튼: [네, 세웠어요] [아직이에요]
- 동작
  - [아직이에요]: "먼저 안전한 곳에 차를 세워 주세요. 이 앱은 차를 세운 뒤에 사용해 주세요"를 보여 주고 홈으로 돌아간다.
  - [네, 세웠어요]: 사고 모드 세션을 시작하고 시작 시각을 기록한 뒤 차량 상태를 1회 읽고 SC-210으로 간다.
- 근거: 속도·기어를 읽을 수 없어 정차 여부는 사용자 확인으로만 판단한다(코드에서 속도·기어를 읽지 않는다).
- 예외: 차량 상태 읽기가 실패해도 SC-210으로 진행한다.
- 확인 방법
  - 두 버튼의 동작이 위와 같다.
  - 차량 상태를 읽을 수 없는 상태에서도 SC-210으로 간다.
  - 하단에 사고 모드 시작 시각이 보인다.

### SC-210 안전 확보 — 체크리스트 템플릿 (Phase 3)

- 체크 항목(큰 체크박스)
  1. 비상등 켜기
  2. 경미한 사고이고 차를 옮길 수 있다면 안전한 곳으로 이동
  3. 동승자는 안전한 곳으로 이동
  4. 도로 위에서 차 밖으로 나갈 때는 주변 차량 확인
- 동작: [다음]은 항상 활성. 체크 결과는 SC-260 요약에 표시한다. "왜 필요한가요?" 짧은 설명 카드를 둔다. [소리로 듣기] 버튼은 Phase 9 전까지 비활성(회색).
- 비고: 비상등은 SDK로 읽을 수 없어 사용자 체크 항목이다.
- 템플릿 규칙: SC-220, 230, 240과 SC-500~520은 이 화면의 구성(진행 목록, 체크 항목, 설명 카드, 하단 바)을 따른다.
- 확인 방법
  - 아무것도 체크하지 않아도 [다음]이 눌린다.
  - 체크 후 [이전]으로 갔다 와도 체크 상태가 유지된다.
  - 체크 결과가 SC-260에 나타난다.

### SC-220 부상 확인 (Phase 3)

- 문구: "다친 사람이 있나요?"
- 버튼: [없어요] [있어요] [잘 모르겠어요]
- 동작: [없어요]는 SC-230으로, [있어요]와 [잘 모르겠어요]는 SC-221로 이동한다. 응답은 세션에 저장한다.
- 안내: "있거나 모르겠으면 119 안내를 먼저 보여 드려요"
- 확인 방법
  - 세 버튼의 이동이 위와 같다.
  - 선택한 응답이 SC-260에 표시된다.
  - 이 화면에는 [다음] 버튼을 두지 않고 세 선택 버튼으로만 이동한다. [이전]으로 나가면 응답은 "응답 안 함"으로 둔다.

### SC-221 긴급 안내 (Phase 3)

- 구성: 가장 눈에 띄는 큰 글자로 "119에 먼저 연락하세요", 큰 본문 "전화로 119를 눌러 주세요"와 "이 앱은 전화를 대신 걸지 않아요. 직접 걸어 주세요.", 112(경찰) 안내("경찰 신고는 112예요."), 연락할 때 말할 내용(맨 위에 "교통사고라고 말해요", 사고 장소의 도로명·이정표, 다친 사람 수와 상태), "참고용 안내이며 법률·의료 조언이 아니에요." 진행 목록과 [사고 모드 나가기]는 두지 않는다(긴급 화면에서 정보를 줄임). [이전]으로 SC-220에 돌아가 나갈 수 있다.
- 동작: [확인했어요]를 누르면 SC-230으로 이동한다. **앱은 전화를 직접 걸지 않는다**(전화 기능 미검증).
- 위치: 위치를 허용하고 주소가 있으면 "말할 내용"에 표시하고, 없으면 "사고 장소를 말로 설명하세요"를 보여 준다(Phase 7~8 이후).
- 비고: 문구는 공식 응급 안내와 대조해 확정한다.
- 확인 방법
  - [확인했어요]로 SC-230에 간다.
  - 위치가 꺼져 있어도 화면이 정상이다.

### SC-230 현장 기록 안내 (Phase 3, 음성 메모는 Phase 11)

- 체크 항목(휴대폰으로 촬영): 두 차량의 전체 모습 / 파손 부위 가까이 / 상대 차량 번호판 / 도로·신호·차선 상황 / 사고 장소 주변
- 동작: "나중에 보험사에 보여 줄 수 있어요"를 안내한다. 앱은 사진을 찍거나 저장하지 않는다("사진은 앱에 저장되지 않아요" 문구 표시).
- 음성 메모 카드: Phase 11 전에는 회색 비활성으로 두고 "음성 사용이 꺼져 있거나 사용할 수 없어요"를 표시한다. Phase 11 이후에는 [말하기] → 듣는 중 → 인식 결과 확인 후 [저장] [다시 말하기].
- 확인 방법
  - 체크하지 않아도 [다음]이 눌린다.
  - 앱에 카메라 호출·사진 저장 코드가 없다.

### SC-240 상대방 정보 확인 (Phase 3)

- 체크 항목: 상대 차량 번호 확인 / 연락처 교환 / 상대 보험사 확인
- 동작: **앱은 상대방 정보를 입력받거나 저장하지 않는다.** 차량 화면에서 타이핑하는 일이 없다. 체크 여부만 세션에 둔다.
- 확인 방법
  - 입력창이 없다.
  - 체크 여부가 SC-260에 "확인함/확인 안 함"으로 나타난다.

### SC-250 차량 상태 기록 (Phase 4)

- 구성
  - 차량 윗면 그림에 열린 문 영역 표시(Row 1~3 좌·우, Hood, Rear)
  - 창문 열림 상태, 배터리, 주행 거리, 방향지시등 상태
  - 기록 시각, [다시 읽기] 버튼, "가상 차량 값" 배지
  - (사용자가 허용한 경우에만) 사고 위치(주소) 카드, 날씨 카드. 허용하지 않으면 카드를 보이지 않거나 점선 안내로 둔다
- 항목 상태: 값 표시 또는 "확인 불가"(미지원 또는 오류)
- 동작: [다시 읽기]는 5개 기능을 다시 읽고 시각을 갱신한다. 이 화면에 들어올 때 SC-200에서 읽은 값을 보여 주고, 필요하면 다시 읽는다.
- 규칙: 읽기 전용, 쓰기 호출 없음. 배터리는 %, 주행 거리는 km를 붙여 표시한다(SDK 문서 기준). 경고 판단은 하지 않는다.
- 확인 방법
  - Virtual Console에서 문을 열고 [다시 읽기]를 누르면 해당 영역이 열림으로 바뀐다.
  - 미지원 항목이 있어도 카드가 표시되고 "확인 불가"가 보인다.
  - 화면을 나갔다 다시 들어와도 리스너 중복 등록 오류가 없다.

### SC-260 접수 요약 (Phase 5)

- 구성
  1. 기록 시각(사고 모드를 시작한 시각이며 실제 사고 시각과 다를 수 있다는 안내)
  2. 부상 여부 응답
  3. 체크리스트 완료 현황(SC-210, 230, 240)
  4. 차량 상태 요약(열린 문·창문을 이름으로 모두 나열, 배터리, 주행 거리, 읽은 시각). "읽은 시각"은 차량 값을 읽은 시각(SC-250의 기록 시각과 같음)이며 1번 "기록 시각"(사고 모드를 시작한 시각)과 다르다. 읽지 못했으면 "확인 불가"
  5. "보험사에 말할 순서" 안내(무슨 일이 있었는지, 장소, 부상 여부, 차량 상태, 상대방 확인 여부)
- 장소: 위치를 허용하지 않았거나 읽지 못하면 "사용자가 말로 설명"하도록 안내한다. 주소가 있으면 표시한다(Phase 8 이후).
- 규칙: 화면 표시만 한다. 이 화면에서 외부로 전송하지 않는다. 과실·책임 판단 문구가 없다. "참고용 기록이며 법적 효력을 보증하지 않아요"를 표시한다.
- 버튼: [기록 저장], [보험사로 전달]은 Phase 10, 12에서 연결한다. 그 전에는 숨기거나 비활성으로 두고, 눌러서 아무 일도 안 일어나는 버튼을 만들지 않는다.
- 확인 방법
  - 앞 단계에서 건너뛴 항목이 "확인 안 함"으로 표시된다.
  - 앞 단계에서 입력한 값이 그대로 요약에 나타난다.

### SC-300 출발 전 점검 (Phase 6)

- 목적: 매일 쓰는 기능으로 재방문 이유를 만들고, 차량 상태 읽기를 평상시에도 보여 준다.
- 점검 항목: 문 모두 닫힘(영역별, Hood·Rear 포함, 0보다 크면 열림) / 창문 모두 닫힘(영역별, 0보다 크면 열림) / 배터리 잔량 / 방향지시등 꺼짐(왼쪽·오른쪽이 켜져 있으면 확인 필요)
- 동작: 화면에 들어오면 읽고 [다시 확인]으로 갱신한다. 결과는 "이상 없음" 또는 "확인 필요 N건"과 항목별 상태 배지로 보여 준다. 읽을 수 없는 항목은 "확인 불가"로 표시하고 **이상으로 세지 않는다.**
- 배터리: 잔량을 %로 보여 주고 경고 판단은 하지 않는다.
- 확인 방법: Virtual Console에서 문을 열고 [다시 확인]을 누르면 "확인 필요 1건"이 나온다. 문을 닫으면 "이상 없음"으로 돌아간다.

### SC-400 차량 연동 상태 (Phase 6)

- 목적: 이 차량에서 무엇이 되고 안 되는지 숨기지 않고 보여 준다.
- 구성: 기능별 행(문 열림, 창문, 배터리, 주행 거리, 방향지시등), 상태 문구 3종(1.5), 마지막 확인 시각. 위치·음성·길안내는 Phase 7 이후 "사용 가능 / 확인 불가" 행으로 추가한다.
- 동작: [다시 확인]을 누르면 지원 여부를 다시 확인한다.
- 확인 방법: 미지원 기능이 있으면 그 행에 "이 차량에서는 지원하지 않아요"가 표시된다.

## 3. 화면별 명세 (P1)

### SC-205 권한·동의 (Phase 7)

- 구성: 제목 "사용할 기능을 골라 주세요", 부제 "필요한 것만 켜세요.". 큰 스위치 3개 — 위치("사고 장소를 기록해요"), 음성("말로 메모를 남겨요"), 네트워크("주소와 날씨를 조회해요"). **기본값은 모두 꺼짐.** 스위치 옆에 "켜짐"/"꺼짐" 글자를 함께 보여 준다. 위치를 켤 때 시스템 권한 창이 뜨고, 허용하지 않으면 스위치를 다시 끄고 "위치 권한을 허용하지 않았어요"를 한 줄 보여 준다. 하단 "꺼 두어도 사고 안내는 끝까지 사용할 수 있어요". 버튼 [이전], [다음].
- 동작: 사고 모드 첫 진입 때 한 번만 보여 준다. 이미 정했으면 건너뛴다. 동의 상태는 SC-200 시작 시 한 줄로 보여 준다. SC-500에서 다시 바꿀 수 있다(확인 필요).
- 규칙: 위치·음성은 여기서 허용한 경우에만 쓴다. 이 차량에서 쓸 수 없는 기능(위치 서비스가 없는 차량의 위치 행)은 스위치를 회색 점선 행으로 두고 설명 줄에 "이 차량에서 사용할 수 없어요", 스위치 옆에 "사용 불가"를 표시한다. 꺼져 있어도 사고 모드는 끝까지 진행된다.
- 확인 방법: 스위치를 켜고 끔에 따라 SC-221, 250, 260의 위치·주소·날씨 표시가 나타나거나 사라진다. 모두 꺼도 SC-260까지 도달한다.

### SC-270 종료와 기록 처리 (Phase 10)

- 구성: 제목 "사고 대응을 마쳤어요", 요약 한 줄(기록 시각 · 차량 상태 개수 · 안내 이행 수), [기록 저장] [저장하지 않고 종료], 안내 "저장하면 이 기기에만 보관되고 언제든 삭제할 수 있어요", "참고용" 문구.
- 동작: **기본 선택은 보관하지 않음.** [저장하지 않고 종료]는 세션 데이터를 즉시 폐기하고 홈으로 간다. [기록 저장]은 최근 1건만 기기 내부 저장소에 둔다. 저장된 기록은 SC-520에서 삭제한다.
- 확인 방법: 저장 후 앱을 다시 실행해도 기록이 남고, 삭제하면 사라진다. 저장하지 않고 종료하면 흔적이 남지 않는다. 상대방 정보·사진·차대번호가 저장 항목에 없다.

### SC-280 다음 장소 안내 (Phase 13)

- 구성: "어디로 갈까요?" 카드 3개 — 안전한 곳으로 이동 / 정비소 / 병원. 카드를 고르면 후보 장소를 보여 주고 [길안내 시작]을 눌러야 NaviHelper로 목적지를 전달한다.
- 주의: NaviHelper에는 장소 검색 API가 없다. 후보 장소의 좌표를 어디서 가져올지는 **구현 전에 사용자와 합의한다.**
- 예외: SDK 연결 실패나 검색 데이터가 없으면 카드를 비활성화하고 이유를 표시한다.
- 확인 방법: [길안내 시작]을 누르기 전에는 어떤 호출도 하지 않는다. 연결 실패 시 앱이 멈추지 않는다.

### SC-290 사고 기록 패키지와 전달 (Phase 12)

- 구성: "시연용 가상 보험사" 배지, 전달할 항목 체크 목록(사고 시각, 위치와 주소, 날씨, 차량 상태, 안내 이행 기록, 음성 메모), 선택 항목 미리보기, [보내기]. "상대방 정보와 사진은 포함되지 않아요" 안내.
- 동작: 사용자가 [보내기]를 눌러야만 전송한다. 보낸 뒤 접수 번호와 전송 항목 로그를 보여 준다. 실패하면 재시도 또는 기기 저장만 선택할 수 있다.
- 규칙: 실제 보험사로 보내지 않는다. 목업 방식은 시작 전에 합의한다. 전송 항목은 체크한 것만 포함한다.
- 확인 방법: 항목을 끄면 미리보기, 전송, 로그에서 모두 빠진다. [보내기]를 누르지 않으면 아무것도 전송되지 않는다.

### SC-500 설정·정보 / SC-510 개인정보 처리 원칙 / SC-520 저장 기록 삭제 (Phase 14)

- SC-500: 앱 소개, 앱 버전과 SDK 버전, SC-510·SC-520 이동.
- SC-510: 수집하지 않는 것(사진, 차대번호, 상대방 연락처. 위치·음성은 허용한 경우만), 외부 전송은 사용자가 켠 경우만, 보관은 사용자 선택, 언제든 삭제 가능.
- SC-520: 보관한 기록이 있으면 요약을 보여 주고 [삭제](확인 대화상자 포함). 없으면 "보관한 기록이 없어요".
- 확인 방법: 삭제 후 SC-520이 "보관한 기록이 없어요"로 바뀐다.

## 4. 전체 수용 기준 (1차 제출 전)

- [ ] 에뮬레이터에서 P0 화면 전체를 시연할 수 있다(SC-100 → 200 → 210 → 220 → 230 → 240 → 250 → 260, 그리고 SC-300, SC-400).
- [ ] 미지원·오류 상황에서 앱이 종료되지 않는다.
- [ ] 쓰기(set) 호출과 CONTROL_* 권한이 없고, 비밀값이 코드·로그·README에 없다.
- [ ] 위치·음성·네트워크를 모두 꺼도 사고 모드가 끝까지 진행된다.
- [ ] 모든 안내 화면에 "참고용" 표시가 있고 법적·과실 판단 문구가 없다.
- [ ] 전체 시나리오를 3회 연속 오류 없이 통과한다.
