# Pit Crew 진행 기록 (PROGRESS)

작업이 끝날 때마다 이 문서를 갱신한다. 다음 날 어디서부터 시작할지 이 문서만 보면 알 수 있어야 한다.
기준 문서: `docs/PLAN.md`(순서), `docs/SPEC.md`(화면 명세), `docs/design/`(디자인), `CLAUDE.md`(규칙)

## 갱신 규칙 (Claude Code)

- 작업 하나(또는 Phase 하나)를 마칠 때마다 **맨 위 "현재 상태"와 아래 "작업 기록"에 항목을 추가**한다.
- 기록은 짧게 쓴다. 한 항목은 5줄 안쪽: 한 일, 확인한 것, 확인하지 못한 것, 다음 할 일.
- **실제로 빌드하고 에뮬레이터에서 확인한 것만 "완료"로 쓴다.** 확인하지 못한 것은 "미확인"으로 구분해 적는다.
- SDK 호출이 에뮬레이터에서 되는지/안 되는지는 결과를 그대로 기록한다(5절). 안 되면 "확인 불가 처리"를 함께 적는다.
- 키, 토큰, 비밀번호, 개인 이메일, 실제 이름·전화번호를 적지 않는다.
- 사용자가 결정해야 하는 일은 "결정 필요" 절에 올리고, 결정되면 "결정 기록"으로 옮긴다.
- 커밋을 만들었다면 커밋 메시지(화면 ID 포함)를 항목에 적는다.

## 4. 알려진 상태와 주의

- 임시 측정 코드(`TEMP-WINSIZE`, Logcat 출력)는 이미 없다. `app/src` 검색으로 확인했다(2026-11-05).
- 샘플 앱의 제어(set) 호출, "Apply change", `onRunSet`은 Phase 0에서 삭제했다. 리플렉션 탐색기는 읽기 전용(`PublicApiPolicy`: check/get/is/register/unregister만 허용, `invoke`에서 한 번 더 검사)으로 남기고 디버그 빌드의 [개발자 도구]에서만 연다. 제출 전 진입점 제거는 PLAN Phase 14.
- 에뮬레이터의 차량 값은 가상 값이다.
- **알려진 한계(Phase 7):** 위치 권한 창의 문구("Pit Crew에서 알 수 없는 작업 실행하도록 허용하시겠습니까?")는 시스템 기본 문구이며 앱에서 바꿀 수 없다.
- **알려진 한계(Phase 8):** 공용 Nominatim 정책의 "OSMF 요청 시 소프트웨어 업데이트 없이 서비스를 바꿀 수 있어야 한다"는 충족하지 못한다(주소 서버가 앱에 고정). 시연용 소규모, 세션당 1회 호출이다. 정책은 예고 없이 바뀔 수 있어 실패하면 "주소 확인 불가"로 처리한다.
- **Phase 14 할 일(SC-270 문구 복원):** SC-270 안내 줄은 지금 "저장하면 이 기기에만 보관돼요."이다. SC-520(저장 기록 삭제)이 생기면 SPEC·시안의 원래 문구 **"저장하면 이 기기에만 보관되고 언제든 삭제할 수 있어요"로 복원**한다(4-1 기록된 예외 참고). 릴리스에는 개발자 도구가 없어 SC-520 전까지는 사용자가 앱 안에서 기록을 지울 수 없다.
- **Phase 14 할 일:** 개발자 도구와 함께 [저장 기록 삭제] 버튼도 제거한다(PLAN 반영).
- **Phase 14 할 일:** 권한을 두 번 거부하면 창 없이 거부 처리되므로, SC-500에 "시스템 설정에서 허용해 주세요" 안내를 넣는다.

### 2026-11-06 — 시작 때 문 지원 확인 시간 초과 (원인 확인, 코드 변경 없음)
- 현상: 앱을 껐다 켠 뒤 홈이 "차량 정보 5개 중 4개"로 나오고, 사고 모드를 시작하면 SC-250·SC-270에서 문 값이 "확인 불가"(차량 상태 4/5)로 기록된다.
- 방법: 에뮬레이터에서 앱을 강제 종료 후 다시 켜기를 16회(A 7회, B 6회, C 3회) 하고 로그(`PitCrewVehicle`, SDK의 `getCapabilityConfig` 요청 줄)를 봤다. 값, 좌표, 주소는 적지 않는다.
