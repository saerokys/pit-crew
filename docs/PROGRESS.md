# Pit Crew 진행 기록 (PROGRESS)

## 갱신 규칙 (Claude Code)

- 작업 하나(또는 Phase 하나)를 마칠 때마다 **맨 위 "현재 상태"와 아래 "작업 기록"에 항목을 추가**한다.
- 기록은 짧게 쓴다. 한 항목은 5줄 안쪽: 한 일, 확인한 것, 확인하지 못한 것, 다음 할 일.
- **실제로 빌드하고 에뮬레이터에서 확인한 것만 "완료"로 쓴다.** 확인하지 못한 것은 "미확인"으로 구분해 적는다.
- SDK 호출이 에뮬레이터에서 되는지/안 되는지는 결과를 그대로 기록한다(5절). 안 되면 "확인 불가 처리"를 함께 적는다.
- 키, 토큰, 비밀번호, 개인 이메일, 실제 이름·전화번호를 적지 않는다.
- 사용자가 결정해야 하는 일은 "결정 필요" 절에 올리고, 결정되면 "결정 기록"으로 옮긴다.
- 커밋을 만들었다면 커밋 메시지(화면 ID 포함)를 항목에 적는다.

## 1-1. 다른 PC에서 이어서 작업하기

이 절에는 키, 토큰, 비밀번호, 개인 이메일, 좌표·주소 값을 쓰지 않는다.

**새 PC에 필요한 환경**
- Android Studio. Gradle JDK는 JDK 21(jbr-21)로 설정한다(JDK 25로는 빌드 실패, 3절).
- Pleos Connect Emulator v2.1.0과 Pleos 시스템 이미지(API 34). 일반 Android Automotive 이미지는 쓰지 않는다.
- 저장소를 clone한다. Maven 저장소(Pleos Nexus)와 SDK 버전은 저장소의 Gradle 설정에 들어 있다.
- **git 신원은 저장소 로컬 설정이라 새 PC에서는 없다.** 새 PC에서 저장소 안에서 `git config user.name`과 `git config user.email`을 다시 설정한다. 이메일은 GitHub 계정 설정의 noreply 주소만 쓰고 개인 이메일은 쓰지 않는다(CLAUDE.md 규칙 8).
- 빌드와 설치: `./gradlew assembleDebug` 뒤 `adb install -r app/build/outputs/apk/debug/app-debug.apk`. 세션을 시작하면 CLAUDE.md와 이 문서 1절을 먼저 읽는다.

**RAM 8GB PC에서 에뮬레이터 실행(낮은 설정)**
- 개발에 쓰는 PC는 RAM이 8GB라서 에뮬레이터 기본 설정(RAM 4096MB, 코어 3)으로는 빌드와 함께 돌릴 때 멈추거나 화면이 까맣게 되는 일이 있었다.
- 낮은 설정 실행: `emulator -avd Pleos_Connect_v2.1.0 -no-snapshot-load -gpu swiftshader_indirect -memory 3072 -cores 2`
- Android Studio는 닫고 에뮬레이터만 PowerShell에서 켠다. Gradle은 JDK 21로 실행한다(Android Studio 번들 JDK 25로는 빌드가 실패한다).
- 해상도와 밀도는 바꾸지 않는다(앱 영역 1682×1210dp, 밀도 160).
- 데모 녹화 때도 같은 설정으로 켠다.

**에뮬레이터 쪽 설정**
- Virtual Console: 에뮬레이터를 켠 뒤 `adb forward tcp:8088 tcp:8088`, PC 브라우저에서 `http://127.0.0.1:8088/`(3절). 문·창문 등 가상 값은 Emulation Controls > Convenience에서 바꾼다.
- 가상 위치를 서울 강남 일대로 지정한다. SC-280의 시연용 후보 장소가 이 일대의 공공 장소라, 내비 앱이 경로를 계산하려면 필요하다(좌표는 코드 `DemoPlaces.kt`에만 있다).
- **내비 앱 화면을 한 번 열어 둔다.** 에뮬레이터를 켠 직후나 내비 앱을 강제 종료한 직후에는 내비 앱이 화면 없이 프로세스만 떠 있어 [길안내 시작] 요청이 버려진다(`navi not ready`, 5절). 하단 바 가운데 내비 아이콘을 눌러 지도 화면을 열면 된다. 앱을 종료해도 시스템이 다시 띄운다.
- Pit Crew가 가려지면 하단 바의 Vehicle SDK 아이콘을 눌러 앞으로 가져온다(이미 앞에 있을 때 누르면 가려진다). 내비 앱을 다시 띄우면 Pit Crew가 홈 화면으로 돌아갈 수 있다.
- 앱을 설치하고 처음 연 직후에는 첫 탭이 앱에 전달되지 않을 수 있다(2번 확인, 로그에 오류 없음). 내비 앱 아이콘 → Vehicle SDK 아이콘으로 앞으로 가져온 뒤에는 정상이었다.
- **데모 상태 되돌리기(개발자 도구가 없어서 앱 밖에서 한다, 아직 실행해 보지 않은 절차):** 사용자 10(AAOS 운전자)에서 앱이 돌아 모든 `pm` 명령에 `--user 10`이 필요하다(없으면 사용자 0에 걸린다, 5절).
  1. 에뮬레이터를 낮은 설정으로 새로 켜고(콜드 부팅), Gradle 데몬이 없고 호스트 여유 RAM이 2GB 이상인지 확인한다. 빌드와 에뮬레이터 조작을 겹치지 않는다.
  2. `adb shell pm clear --user 10 ai.pleos.playground.sample.vehicle`로 동의, 저장 기록, 앱 데이터를 지운다(앱 프로세스가 종료되므로 에뮬레이터가 멈출 수 있다).
  3. 위치 권한이 `pm clear`로 같이 되돌아가는지는 실행해 봐야 안다. 안 되돌아가면 `adb shell pm revoke --user 10 ai.pleos.playground.sample.vehicle pleos.car.permission.FUSED_LOCATION`을 쓴다. 한 번 "허용하지 않고 다시 묻지 않음"을 누른 권한은 `USER_FIXED`가 붙어 권한 창이 다시 뜨지 않을 수 있다(시험 때 `grant` 뒤에도 `USER_FIXED`가 남아 있었다). 이때는 `pm clear`가 필요하다.
  4. 시험 조작 주의: 권한 창의 두 버튼은 [허용]이 위, [허용하지 않고 다시 묻지 않음]이 아래다.
  5. 대안: 앱 재설치(`adb uninstall` 뒤 `install`)도 같은 효과이고 같은 위험(프로세스 종료)이 있다.

## 4. 알려진 상태와 주의

- 임시 측정 코드(`TEMP-WINSIZE`, Logcat 출력)는 이미 없다. `app/src` 검색으로 확인했다(2026-11-05).
- 샘플 앱의 제어(set) 호출, "Apply change", `onRunSet`은 Phase 0에서 삭제했다. 읽기 전용 리플렉션 탐색기와 [개발자 도구]도 Phase 14 단계 4에서 코드째 모두 지웠다(릴리스 dex 검색 0건).
- 에뮬레이터의 차량 값은 가상 값이다.
- **알려진 한계(Phase 7):** 위치 권한 창의 문구("Pit Crew에서 알 수 없는 작업 실행하도록 허용하시겠습니까?")는 시스템 기본 문구이며 앱에서 바꿀 수 없다.
- **알려진 한계(Phase 8):** 공용 Nominatim 정책의 "OSMF 요청 시 소프트웨어 업데이트 없이 서비스를 바꿀 수 있어야 한다"는 충족하지 못한다(주소 서버가 앱에 고정). 시연용 소규모, 세션당 1회 호출이다. 정책은 예고 없이 바뀔 수 있어 실패하면 "주소 확인 불가"로 처리한다.
- **후속 과제(2차 PT 12/3 전):** SC-280 후보 장소를 실제 장소 검색으로 바꾸는 것을 다시 검토한다(키 없음, 3초, 정책·응답 시간 확인, 사용자 좌표 저장·로그 금지). 지금은 앱에 넣은 시연용 목록이다(PLAN 후속 과제).
- **Phase 14(날씨 출처, 구현함):** SC-510에 Open-Meteo 출처 "Weather data by Open-Meteo.com"(CC BY 4.0)와 "날씨를 조회하면 서버 로그에 좌표가 최대 90일 남을 수 있어요"를 넣었다(2026-11-07). 화면에서는 링크를 누를 수 없고 링크(https://open-meteo.com/)는 README에 있다.
- **Phase 14 SC-500 권한 거부 안내(구현함, 확인함):** 위치 권한을 거부하면 SC-205 문구 "위치 권한을 허용하지 않았어요", `shouldShowRequestPermissionRationale`가 false이면 "시스템 설정에서 허용해 주세요"를 글자로만 보여 준다. 이 에뮬레이터의 권한 창에는 [허용]과 [허용하지 않고 다시 묻지 않음]뿐이라 첫 거부부터 안내가 뜨고(로그 `rationale=false`), 세 번째 시도는 창 없이 바로 거부되어 안내가 그대로 보였다(5절).
- **알려진 한계(Phase 14 단계 2, SC-500 권한 거부 안내):** (1) 한 번도 거부한 적이 없는데 권한 창이 거부로 닫히면(창 바깥을 누르거나 다른 화면이 올라온 경우 등) `shouldShowRequestPermissionRationale`가 false라서 "시스템 설정에서 허용해 주세요"가 뜰 수 있다(실제로 생기는지는 확인하지 못함). (2) 안내가 뜬 뒤 사용자가 시스템 설정에서 허용하고 돌아와도 안내 글자는 스위치를 누르거나 화면을 나갈 때까지 남아 있다. (3) Activity를 찾지 못하거나 시스템이 rationale을 true로 주면 안내가 뜨지 않는다(앱은 정상 동작하고 위치만 꺼진 채). (4) 판별 호출이 예외를 던지면 안내를 띄우지 않는다(`try/catch`, 사용자 결정 (나)). 사용자는 (3)·(4) 외의 개선은 하지 않기로 했다(2026-11-07). 위 (1)은 이 에뮬레이터 권한 창에 "허용하지 않고 다시 묻지 않음"뿐이라 창 바깥을 눌러 닫는 경우만 남고, 그 경우는 시험하지 못했다.
- **남겨 둔 것(Phase 14 단계 4, 사용자 결정 K·L):** (1) `kotlin-reflect` 의존성(`libs.versions.toml`, `app/build.gradle.kts`)은 탐색기만 쓰던 것이라 지금은 쓰이지 않지만 이번에는 건드리지 않았다(제출 준비에서 지울지 정한다). (2) 구 샘플 테마 `ui/theme/`(`VehicleSampleAppTheme`)는 `MainActivity`가 감싸는 데 쓰고 있어 그대로 둔다. (3) `debugImplementation`의 Compose 도구 의존성은 그대로다.
- **권한 정리(2026-11-08, 위험을 그대로 기록):** 샘플 앱에서 온 차량 권한 20개 중 15개를 매니페스트에서 지웠다. 남긴 것은 코드가 실제로 부르는 5개뿐이다(`CAR_DOORS` 문, `CAR_WINDOWS` 창문, `CAR_ENERGY` EV SoC, `CAR_DRIVE` 주행 거리(odometer)만, `CAR_LIGHTS` 방향지시등). 근거는 SDK 2.3.2 소스의 `@RequiresPermission`이다(코드의 차량 SDK 호출은 check 5개와 get 5개뿐, set과 리스너 없음). (가) **지운 9개는 에뮬레이터에서 정의가 없어 영향 확인이 불가능하다**(SDK 소스에도 없고 어떤 패키지도 정의하지 않음): `CAR_CONNECT_VENDOR_CONTROL`, `CAR_MILEAGE`, `CAR_POWERTRAIN`, `CAR_SPEED`, `CAR_TIRES`, `READ_CAR_DISPLAY_UNITS`, `READ_CAR_STEERING`, `READ_ADAS_STATES`, `READ_WINDSHIELD_WIPERS`. 서비스 APK는 읽을 수 없어(`Permission denied`) 서비스 쪽이 이 이름을 검사하는지 확인하지 못했다. **실제 차량에서 연결이 안 되면 되살린다.** (나) 지운 6개는 에뮬레이터에 정의돼 있지만 코드가 부르는 API가 요구하지 않는다: `CAR_CLIMATE`, `CAR_INFO`, `CAR_MIRRORS`, `CAR_SAFETY`, `CAR_SEATS`, `CAR_TOLL`. (다) 에뮬레이터 확인 규칙: 지운 뒤 UNSUPPORTED나 UNKNOWN이 새로 나오거나 `SecurityException`이 나면 해당 권한을 되살리고 이유를 5절에 기록한다. 확인 결과는 8절 맨 위 기록에 적는다.
- **제출 준비 할 일(시연 영상 녹화 전, SC-280):** (1) 내비 앱 화면을 한 번 열어 둔다. 내비 앱이 화면 없이 프로세스만 떠 있거나 방금 강제 종료된 상태에서는 [길안내 시작] 요청이 버려지고(`navi not ready`) [다시 시도]도 소용없다(에뮬레이터는 내비 앱을 종료해도 시스템이 다시 띄우므로 화면을 직접 열어야 한다). (2) 이전 경로는 매번 내비 앱의 [안내 종료]로 닫는다. 안내 중에 내비 앱이 종료되면 다시 뜰 때 "경로 안내 재시작" 대화상자가 나온다. (3) 녹화 직전에 [길안내 시작]을 한 번 눌러 "길안내를 시작했어요"가 나오는지 확인하고 [안내 종료]로 닫는다.

[저장하지 않고 종료]는 아무것도 저장하지 않고 홈으로 갑니다. 저장한 기록은 SC-520에서 보고 지울 수 있습니다(아래).

> 소리로 듣기(Phase 9): SC-205에서 음성을 켜면 SC-210, 220, 221, 230, 240 상단 바의 [소리로 듣기]로 그 화면의 안내 문구를 읽어 줍니다(TextToSpeech `ON_DEVICE`, 한국어). 자동 재생은 없고 누를 때만 읽으며, 읽는 중에는 [멈추기]가 됩니다. 화면을 옮기거나 앱이 화면에서 사라지면 멈추고, 사고 모드가 끝나 홈에 도착하면 해제합니다. 주소와 좌표는 읽지 않습니다. 초기화 실패나 재생 오류는 "소리 안내 불가"로 보이고 사고 모드는 계속됩니다. 에뮬레이터에서는 이벤트와 오디오 상태로만 확인했고 실제 소리와 발음은 확인하지 못했습니다.

> 주소 변환(Phase 8): 위치와 네트워크 스위치를 모두 켠 경우에만, 사고 모드 시작 때 위치를 읽은 뒤 좌표(소수점 4자리 반올림)를 OpenStreetMap Nominatim에 보내 주소 한 줄(시/도 구 도로명 번호)을 받아 SC-221, SC-250, SC-260에 보여 줍니다. 좌표는 호출에만 쓰고 세션에는 주소 문자열과 상태만 메모리로 보관하며 저장·로그·화면 표시를 하지 않습니다. 상호(name)는 버립니다. 네트워크 스위치를 켜면 SC-205에 "켜면 사고 위치를 주소·날씨 조회 서버로 보내요" 안내가 보입니다. 3초 안에 응답이 없거나 네트워크가 끊기면 "주소 확인 불가"로 표시하고 사고 모드는 계속됩니다. 상대방 정보, 사진, 차대번호와는 섞지 않습니다.

> 권한·동의와 위치(Phase 7): 사고 모드에 처음 들어갈 때 한 번 SC-205에서 위치, 음성, 네트워크 스위치(기본 꺼짐)를 고릅니다. 선택은 앱을 껐다 켜도 유지되며 저장하는 값은 켜짐/꺼짐뿐입니다. 위치를 켜면 시스템 권한 창이 뜨고, 허용한 경우에만 사고 모드 시작 때 마지막 위치를 한 번 읽어 세션 메모리에 둡니다(저장·전송·화면 표시 없이 "위치 확인됨" 같은 상태만 보여 줍니다, 주소 변환은 이후 단계). 읽지 못하면 "확인 불가"로 표시하고, 모두 꺼도 사고 모드는 끝까지 진행됩니다. 음성·네트워크 스위치는 값만 저장합니다(해당 기능은 이후 단계). 선택은 홈의 "설정·정보"(SC-500)에서 다시 바꿀 수 있습니다. 시연을 반복하려고 처음 상태로 되돌릴 때는 앱 밖에서 `adb shell pm clear --user 10 …`을 씁니다(PROGRESS 1-1절). 시험할 때 에뮬레이터 앱은 사용자 10으로 돌아 `adb shell pm grant --user 10 …`처럼 사용자를 지정해야 합니다.

> 출발 전 점검·연동 상태(Phase 6): 홈의 [출발 전 점검](SC-300)은 들어올 때와 [다시 확인]을 누를 때 문(앞쪽 덮개·뒤쪽 포함), 창문, 배터리, 방향지시등을 읽어 "이상 없음" 또는 "확인 필요 N건"으로 보여 줍니다(열림 기준은 값이 0보다 큰 것, 방향지시등이 켜져 있으면 확인 필요, 읽지 못한 항목은 "확인 불가"이며 이상으로 세지 않음, 배터리는 값만 표시). 사고 모드 세션과 무관하며 읽기 전용입니다. [차량 연동 상태](SC-400)는 문, 창문, 배터리, 주행 거리, 방향지시등의 지원 여부("읽을 수 있어요" / "이 차량에서는 지원하지 않아요" / "확인하지 못했어요")와 마지막 확인 시각을 보여 주고, [다시 확인]은 지원 여부를 다시 확인합니다(홈의 "차량 정보 5개 중 N개" 문구도 같은 값을 씁니다).

> 접수 요약(Phase 5): SC-250 다음에 SC-260 접수 요약. 보험사에 말할 순서(무슨 일, 사고 장소, 다친 사람, 차량 상태, 상대방 확인)와 기록 시각, 체크 현황(확인함/확인 안 함)을 보여 줍니다. 화면 표시만 하며 저장하거나 외부로 전송하지 않습니다. 위치, 사진, 상대방 정보, 차대번호는 표시하지 않습니다.

> 차량 상태(Phase 4): SC-200 [네, 세웠어요]에서 문, 창문, 배터리, 주행 거리, 방향지시등을 한 번 읽어 사고 모드 세션에 메모리로만 보관하고, SC-250에서 보여 줍니다([다시 읽기]로 갱신). 읽기 전용(get 호출만, 리스너 없음)이며 읽지 못한 항목은 "확인 불가"로 표시합니다. 값은 에뮬레이터의 가상 값입니다.

> 사고 모드(Phase 3-c): SC-230 현장 기록 안내(휴대폰으로 촬영할 항목 체크 5개, 앱은 사진을 찍거나 저장하지 않으며 카메라 기능이 없음, 음성 메모는 아직 비활성)와 SC-240 상대방 정보 확인(체크 3개, 입력창 없음, 상대방 정보는 저장하지 않음). 체크 여부는 사고 모드 세션에만 메모리로 보관합니다.

> 사고 모드(Phase 3-b): SC-210 다음에 SC-220 부상 확인(없어요/있어요/잘 모르겠어요, 응답은 세션에 메모리로만 보관). 있어요·잘 모르겠어요는 SC-221 긴급 안내(119·112 안내만, 앱은 전화를 걸지 않음)를 거쳐 SC-230으로 갑니다. SC-221 문구는 초안입니다.

> 사고 모드(Phase 3-a): 홈에서 [사고가 났어요] → SC-200 정차 확인(사용자 확인으로만 판단, 속도·기어를 읽지 않음) → SC-210 안전 확보(체크 4개, 체크 상태는 사고 모드 세션에 메모리로만 보관하고 홈에 돌아오면 버림). 나머지 단계는 자리표시 화면입니다.

> 홈(Phase 2): 앱을 켜면 SC-000이 Vehicle SDK를 초기화하고 문·창문·배터리·주행 거리·방향지시등의 지원 여부(읽기 가능/미지원/확인 실패)만 확인한 뒤 SC-100 홈으로 이동합니다. 초기화가 실패해도 홈으로 가고 차량 연동만 끕니다. 값 읽기는 하지 않습니다. 시작 때 시간 안(기능별 3초)에 응답하지 못한 기능(UNKNOWN)은 홈으로 간 직후 한 번만 다시 확인하고, 사고 모드 시작(SC-200)과 출발 전 점검(SC-300)의 읽기 전에도 아직 UNKNOWN인 기능만 다시 확인합니다(읽기 전용, 한 번에 하나씩, 실패하면 "확인 불가"). 실제 차량에서의 동작은 확인하지 못했습니다.

> 공통 틀(Phase 1): 테마 `ui/theme/pitcrew/`, 공통 컴포넌트 `ui/components/`(상단·하단 바, 단계 막대, 버튼, 체크 항목, 카드, 상태 배지), 화면 이동 틀 `ui/nav/`. (Phase 14에서 지운 디버그 전용 컴포넌트 미리보기는 더 이상 없습니다.)

> 화면 이름과 세부 동작은 개발이 진행되는 대로 이 표에 갱신합니다. 기준 문서: 「Pit Crew 기획서 및 MVP 상세 정의서」.

## 6. 사용 권한과 지원하지 않는 항목

### 선언한 권한

차량 제어(set 호출, `CONTROL_*` 권한)는 사용하지 않습니다. 차량 권한은 값을 읽는 데 필요한 5개만 선언합니다.

| 권한 | 종류 | 용도 |
|---|---|---|
| `pleos.car.permission.CAR_DOORS` | 차량 읽기 | 문 위치 |
| `pleos.car.permission.CAR_WINDOWS` | 차량 읽기 | 창문 위치 |
| `pleos.car.permission.CAR_ENERGY` | 차량 읽기 | EV 배터리 충전량 |
| `pleos.car.permission.CAR_DRIVE` | 차량 읽기 | 주행 거리 읽기에만 사용(속도와 기어는 읽지 않음) |
| `pleos.car.permission.CAR_LIGHTS` | 차량 읽기 | 방향지시등 |
| `pleos.car.permission.FUSED_LOCATION` | 위치(런타임 허용 필요) | 사고 위치 1회 읽기. 사용자가 SC-205에서 켠 때 시스템 권한 창으로 허용 |
| `pleos.car.permission.TTS_SERVICE` | 서비스 일반 권한(차량 권한 아님) | 음성 안내 |
| `pleos.car.permission.STT_SERVICE` | 서비스 일반 권한(차량 권한 아님) | 음성 메모 |
| `pleos.car.permission.NAVI_ROUTE_SEARCH` | 서비스 일반 권한(차량 권한 아님) | 길안내 요청(`NAVI_ROUTE`는 선언하지 않음) |
| `android.permission.INTERNET` | 일반 네트워크 권한(차량 권한 아님) | 주소·날씨 조회 |

- 서비스·일반 권한은 설치 때 자동 허용되고, 위치 권한만 사용자가 허용해야 합니다.
- 공식 샘플 앱이 선언하던 나머지 차량 권한 15개는 이 앱이 쓰지 않아 지웠습니다. 그중 9개(`CAR_CONNECT_VENDOR_CONTROL`, `CAR_MILEAGE`, `CAR_POWERTRAIN`, `CAR_SPEED`, `CAR_TIRES`, `READ_CAR_DISPLAY_UNITS`, `READ_CAR_STEERING`, `READ_ADAS_STATES`, `READ_WINDSHIELD_WIPERS`)는 에뮬레이터에서 정의가 없어 **실제 차량에서의 영향은 확인하지 못했습니다.**

### 지원하지 않는 항목

- 사고 자동 감지, 에어백 상태, 문 잠김, 차대번호(VIN), 비상등 자동 확인, 타이어 값
- 법적 판단·과실 판단·의료 조언
- 상대방 정보, 사진, 차대번호의 저장·전송
- 차량 화면에서의 타이핑 입력
- 실제 보험사 연동 (시연용 목업만 제공)
- 사고 기록 내보내기(PDF): 이번 버전(1차 제출)에서는 지원하지 않습니다. 지금은 앱 안에서 요약을 보고 지우는 것까지만 되고, 파일로 내보내는 기능은 없습니다. 서류 통과 후 2차 PT 전까지 만들 예정이지만 아직 구현되어 있지 않습니다.
- 기록 무결성(저장 기록이 바뀌지 않았음을 확인하는 기능): 이번 버전에서는 지원하지 않습니다. 저장 기록은 앱 내부 JSON 파일 하나이고 해시나 서명이 없어서 변조 여부를 확인할 수 없습니다. 이후 고도화 예정이며 아직 구현되어 있지 않습니다.

### 확인하지 못한 것

- **실제 차량**: 모든 기능을 에뮬레이터에서만 확인했습니다. 차량 값은 가상 값입니다.
- **음성 안내(TTS)의 실제 소리와 한국어 발음**("일일구/일일이" 포함): 이 환경에 소리 출력 장치가 없어 이벤트와 오디오 상태로만 확인했습니다.
- **음성 메모(STT)의 실제 한국어 인식**: 마이크가 없어 호출 흐름, 해제, 화면 상태만 확인했습니다.
- **길 계산 범위**: 앱은 목적지를 내비 앱에 전달할 뿐이고, 내비 앱이 어떤 지도 데이터로 어디까지 경로를 만드는지는 확인하지 못했습니다.
- 인터넷이 끊긴 상태에서의 음성 안내·음성 메모·길안내 동작. (주소·날씨는 항공 모드에서 "확인 불가"로 표시되고 앱이 계속 동작하는 것을 확인했습니다.)
- 주행 중 플랫폼이 이 앱의 사용을 제한하는지. 앱은 속도·기어를 읽지 않고 사용자에게 정차를 확인하며, 주행 중 제한은 플랫폼이 처리한다고 보고 별도 차단을 만들지 않았습니다.
- 긴급 안내(SC-221) 문구의 공식 안내(경찰청·보험업계·응급) 대조: **문구는 초안이며 대조를 마치지 못했습니다.**
- 지운 차량 권한 9개의 실제 차량 영향(위 "선언한 권한" 참고).

### 알려진 한계

- 위치 권한 창의 문구("Pit Crew에서 알 수 없는 작업 실행하도록 허용하시겠습니까?")는 시스템 기본 문구이며 앱에서 바꿀 수 없습니다.
- 위치 권한을 거부하면 "위치 권한을 허용하지 않았어요"를 보이고, 다시 묻지 않는 상태이면 "시스템 설정에서 허용해 주세요"를 글자로만 보여 줍니다(설정을 여는 버튼은 없음). 권한 창 바깥을 눌러 닫는 경우는 시험하지 못했고, 안내가 뜬 뒤 시스템 설정에서 허용하고 돌아와도 스위치를 누르거나 화면을 나갈 때까지 글자가 남습니다.
- 공용 Nominatim 서버는 사용 정책(초당 1회 이하, 앱을 식별하는 User-Agent, 출처 표기)을 지켜 시연용 소규모로만 씁니다. 정책이 요구하는 "운영 측 요청 시 앱 업데이트 없이 서비스 전환"은 지원하지 않습니다(주소 서버가 앱에 고정).
- Open-Meteo 무료 API는 비상업 용도로만 쓸 수 있습니다. **상업적 사용 시 유료 요금제가 필요합니다.** 날씨를 조회하면 서버 로그에 좌표가 **최대 90일** 남을 수 있습니다(공식 약관 기준, 앱은 좌표를 소수점 2자리로 반올림해 보냅니다).
- 길안내 후보는 시연용 예시 목록입니다. 에뮬레이터에서 내비 앱 화면이 열려 있지 않으면(강제 종료 직후 등) 길안내 요청이 내비 앱에서 버려집니다. 실제 장소 검색은 2차 PT 전에 다시 검토할 후속 과제입니다.
- 앱을 처음 켠 직후 문·창문의 지원 확인이 제한 시간(3초) 안에 끝나지 않을 수 있습니다. 이때 홈으로 간 직후 한 번 다시 확인하고, 사고 모드 시작(SC-200)과 출발 전 점검(SC-300) 읽기 전에도 아직 확인하지 못한 기능만 다시 확인합니다. 그래도 안 되면 "확인 불가"로 표시합니다.
- 사고 기록은 최근 1건만 저장하며 새로 저장하면 이전 기록이 바뀝니다.

## 7. 개인정보 원칙

- 위치·음성은 SC-205에서 사용자가 허용한 경우에만 사용합니다. 꺼져 있어도 사고 모드는 끝까지 진행됩니다.
- 기록 저장(SC-270)과 외부 전송은 사용자가 켠 경우에만 이루어집니다. 저장 기록에는 좌표, 부상 응답, 상대방 정보, 사진, 차대번호, 음성 메모가 없습니다. 보험사 전송(목업)은 사용자가 [보내기]를 눌러야 하며, 항목별 선택과 전송 로그를 보여 줍니다.
- 좌표는 주소·날씨 조회에만 잠시 쓰고 저장·로그·화면 표시를 하지 않습니다. 로그에도 주소, 음성 메모 내용, 읽어 준 문장은 남기지 않습니다(단계별 결과 종류와 글자 수 같은 것만 남깁니다).
- 키, 토큰, 비밀번호, 개인 이메일을 코드·로그·문서에 넣지 않습니다.

### 기능별 동작

**위치·주소·날씨 (SC-205 → SC-200 → SC-221/250/260)**
- SC-205에서 위치를 켜면 시스템 권한 창이 뜹니다. 허용한 경우에만 사고 모드 시작 때 마지막 위치를 한 번 읽어 세션 메모리에 두고, 화면에는 "위치 확인됨" 같은 상태만 보여 줍니다. 읽지 못하면 "확인 불가"로 표시합니다.
- 위치와 네트워크를 모두 켠 경우에만, 좌표를 반올림해 주소(Nominatim)와 날씨(Open-Meteo)를 각각 한 번 조회합니다. 3초 안에 응답이 없거나 네트워크가 끊기면 "주소 확인 불가", 회색 "확인 불가" 날씨 카드로 표시하고 사고 모드는 계속됩니다.
- 주소는 SC-221, SC-250, SC-260에, 날씨는 SC-250에만 보입니다. 주소 문구는 시/도 구 도로명 번호이며 상호는 버립니다. 주소가 보일 때마다 "© OpenStreetMap contributors"를, 날씨 값 옆에 "Weather data by Open-Meteo.com"를 표시합니다.

**차량 상태 (SC-200 → SC-250, SC-300, SC-400)**
- 읽기 전용입니다(get 호출만, 리스너 없음). 지원 확인(capability)을 먼저 하고, 읽을 수 있는 기능과 확인된 영역만 읽습니다. 문은 앞쪽 덮개와 뒤쪽을 포함하고, 창문은 값이 0보다 크면 열림입니다.
- SC-300은 방향지시등이 켜져 있으면 "확인 필요", 읽지 못한 항목은 "확인 불가"로 보여 주며 이상으로 세지 않고, 배터리는 값만 표시합니다.

**음성 안내 (TTS)**
- SC-205에서 음성을 켜면 SC-210, 220, 221, 230, 240 상단 바의 [소리로 듣기]로 그 화면의 안내 문구를 읽어 줍니다. 자동 재생은 없고 누를 때만 읽으며, 읽는 중에는 [멈추기]가 됩니다. 주소와 좌표는 읽지 않습니다.
- 화면을 옮기거나 앱이 가려지거나 사고 모드가 끝나면 멈추고 해제합니다. 초기화 실패나 재생 오류는 "소리 안내 불가"로 보이고 사고 모드는 계속됩니다.

**음성 메모 (STT, SC-230)**
- 음성을 켠 경우에만 [말하기]를 눌러 한 번 듣습니다(한국어, 최대 30초, [멈추기] 가능). 말하기 전에 "상대방 이름·번호·연락처는 말하지 마세요"를 보여 줍니다. 인식 결과(최대 100자)를 확인한 뒤 [저장] 또는 [다시 말하기]를 고릅니다.
- 메모는 사고 모드 세션 메모리에만 두고 디스크에 쓰지 않으며 사고 기록에도 넣지 않습니다(홈으로 가면 사라짐). 오디오는 받지도 저장하지도 않고(SDK가 돌려주는 텍스트만 사용), 로그에는 글자 수만 남깁니다.
- 못 알아들으면 "잘 듣지 못했어요. 다시 말해 주세요."를 보이고 대기로 돌아갑니다. 초기화 실패 등 사용할 수 없으면 카드가 회색으로 바뀌고 사고 모드는 계속됩니다.

**가상 보험사 전달 (SC-290)**
- SC-260의 [보험사로 전달]로 들어갑니다. **실제 보험사로 전달되지 않으며 앱 안 모의 처리라 외부 호출과 네트워크를 쓰지 않습니다**("이 전송은 시연용이라 네트워크를 쓰지 않아요"가 항상 보입니다). 실제 보험사 이름이나 로고는 쓰지 않습니다.
- 전달 항목은 사고 시각, 위치와 주소, 날씨, 차량 상태, 안내 이행 기록, 음성 메모 6개이고, 사용자가 항목별로 고른 뒤 [보내기]를 눌러야만 접수합니다(값이 없는 항목은 고를 수 없음, 음성 메모는 보내기 전에 내용 전체를 다시 보여 줌). 부상 응답, 상대방 정보, 사진, 차대번호, 좌표는 항목에 없습니다.
- 접수 번호는 "MOCK-"로 시작하는 시연용 번호입니다. 접수 번호, 보낸 시각, 보낸 항목 이름(값 제외)으로 된 전송 로그는 세션 메모리에만 있고 사고 기록에 들어가지 않으며 홈으로 가면 사라집니다.

**기록 저장과 삭제 (SC-270, SC-520)**
- [기록 저장]은 사용자가 누를 때만 사고 시각, 위치·주소(위치 상태와, 조회에 성공했으면 주소와 출처 표기), 날씨(성공했을 때만), 차량 상태, 안내 이행(체크한 항목)을 이 기기의 앱 내부 저장소(백업에서 제외되는 `noBackupFilesDir`, JSON 한 파일)에 최근 1건만 저장합니다. 좌표는 저장하지 않고, 부상 응답·상대방 정보·사진·차대번호·음성 메모도 저장하지 않습니다.
- 위치를 껐거나 읽지 못했거나 주소 조회에 실패하면 기록에 그 상태만 남습니다. 저장하지 못하면 "저장하지 못했어요"가 보이고 앱은 계속 동작합니다. [저장하지 않고 종료]는 아무것도 저장하지 않고 홈으로 갑니다.
- 저장한 기록은 SC-520(홈 → 설정·정보 → 저장 기록 삭제)에서 요약(기록 시각 · 차량 상태 N/5 · 안내 이행 N/12와 위치·주소·날씨 한 줄)을 보고 [삭제]할 수 있습니다. 삭제 전 확인 창("기록을 삭제할까요? 삭제하면 되돌릴 수 없어요")이 뜨고, 삭제하면 "보관한 기록이 없어요"가 보입니다. 기록 파일을 읽지 못하면 "기록을 읽지 못했어요"와 [삭제]를 보여 줍니다.

**길안내 (SC-280)**
- SC-270의 [다음 장소 안내]로 들어가 "안전한 곳으로 이동 / 정비소 / 병원" 중 하나와 후보 하나를 고르고 [길안내 시작]을 누르면 NaviHelper(`requestRoute`)로 내비 앱에 목적지를 전달합니다. 연결은 이 화면에 있는 동안에만 하고 요청은 [길안내 시작]을 눌러야만 합니다. 사용자 위치는 쓰지 않고 거리도 보여 주지 않습니다.
- 연결에 실패하면 버튼이 비활성이 되고, 요청 결과 이벤트가 15초 안에 오지 않으면 "길안내가 시작됐는지 확인하지 못했어요"와 "내비게이션 앱이 열려 있는지 확인해 주세요."를 보여 줍니다.

**설정·정보와 개인정보 처리 원칙 (SC-500, SC-510)**
- SC-500의 스위치(SC-205와 같은 문구)는 바꾸면 바로 저장합니다. 음성을 끄면 쓰던 TTS·STT를 해제하고, 시스템 설정에서 위치 권한을 뺐으면 위치는 꺼진 것으로 보입니다.
- SC-510에는 원칙 4줄("수집하지 않는 것: 사진, 차대번호, 상대방 연락처(위치·음성은 허용한 경우만)", "외부 전송은 사용자가 켠 경우만", "보관은 사용자 선택", "언제든 삭제 가능")과 출처·안내(Open-Meteo CC BY 4.0, 날씨 조회 시 서버 로그에 좌표가 최대 90일 남을 수 있음, OpenStreetMap ODbL 1.0, 시연용 가상 보험사)가 있습니다. 화면에서 링크를 누를 수는 없고 링크는 이 문서 4절에 있습니다.

### SDK별 동작

| SDK | 호출 순서 | 해제 |
|---|---|---|
| FusedLocation | `isSupported()` → `initialize()` → `getLastKnownLocation()` (사고 모드 시작 시 1회) | `release()` |
| NaviHelper | `initialize(onConnected, onFailed)` → 연결 후 리스너 등록 → `requestRoute()` (사용자 선택 시) | `removeListener()` → `release()` |
| TextToSpeech | `Mode.ON_DEVICE`로 생성 → `initialize()` → `addEventListener()` → `speak()` | `stop()` → `removeEventListener()` → `release()` |
| SpeechToText | `Mode.ON_DEVICE`로 생성 → `initialize()` → `addListener()` → `request()` | `stop()` → `removeListener()` → `release()` |

공통 규칙: capability 확인 후 읽기, 모든 SDK 호출은 예외 처리, 리스너는 한 번만 등록하고 화면을 떠날 때 해제.

공통 화면 틀: 테마 `ui/theme/pitcrew/`, 공통 컴포넌트 `ui/components/`(상단·하단 바, 단계 막대, 버튼, 체크 항목, 카드, 상태 배지, 스위치), 화면 이동 틀 `ui/nav/`.

개발 과정에서 단계별로 정한 것과 시험 결과는 `docs/PROGRESS.md`(진행 기록, 9절에 이 문서의 옛 단계별 설명 원문)에 있습니다.
