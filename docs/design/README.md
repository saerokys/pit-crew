# 디자인 반영 정책 (docs/design)

Pit Crew의 화면은 Figma Make로 시안을 만들고, 실제 앱은 Kotlin + Jetpack Compose로 개발한다.
Figma Make 결과물은 웹(React) 코드라서 **Android 프로젝트에 가져오지 않는다.** 시안은 "보고 따라 만드는 기준"이고, 코드는 처음부터 Compose로 작성한다.

## 1. 이 폴더에 두는 것

```
docs/design/
├─ README.md          ← 이 문서 (정책)
├─ tokens.md          ← 색, 글자, 간격, 버튼 값 (스타일 가이드에서 옮긴 값)
├─ STYLE-GUIDE.png    ← 스타일 가이드 (확정됨)
├─ SC-100.png         ← 화면 시안, 파일 이름은 화면 ID
├─ SC-200.png
├─ SC-210.png
├─ SC-210_voice-off.png   ← 같은 화면의 다른 상태는 _상태이름을 붙인다
└─ ...
```

- 시안이 없는 화면(SC-000, SC-240, SC-500, SC-510, SC-520)은 이 폴더에 파일이 없는 것이 정상이다. 이 화면들은 SC-210 시안과 `tokens.md`를 따라 만든다.
- 이미지 크기는 **1682×1210px, 1x**로 내보낸다. 크기가 다르면 비교가 어긋나므로 다시 내보낸다.
- 시안 파일에는 키, 토큰, 개인 정보, 실제 이름·번호를 넣지 않는다.

## 2. 스타일 가이드와 토큰

- **스타일 가이드(`STYLE-GUIDE.png`)와 `tokens.md`가 모든 화면의 색·글자·모양 기준이다.** 화면 시안이 이 기준과 다르면 스타일 가이드가 우선이고, 다른 점은 사용자에게 알린다.
- 색은 `tokens.md`에 있는 hex 값만 쓴다. 새 색을 만들거나 임의로 바꾸지 않는다. 앰버·오렌지 계열은 쓰지 않는다.
- 디자인 방향: 현대차 브랜드 블루 바탕에 밝은 포인트 블루(#00AAD2) 하나로 "여기를 누르세요"를 알려 주는 다크 테마. 상태(정상/주의/긴급/확인 불가)는 색만으로 구분하지 않고 항상 아이콘과 글자를 함께 쓴다.
- **채운 포인트 블루 버튼은 한 화면에 1개만** 둔다. 이 버튼 안의 글자는 흰색이 아니라 짙은 남색(#00122B)이다.
- 시안에 `TODO`로 남은 값(`tokens.md` 7절)은 추측하지 않고 묻는다.

## 3. 내보내기 규칙 (사용자가 하는 일)

1. Figma Make에서 화면 하나가 확정되면 PNG로 내보낸다(1x).
2. 파일 이름을 화면 ID로 바꾼다. 예: `SC-100.png`. 상태가 여러 개면 `SC-230_voice-off.png`처럼 쓴다.
3. 이 폴더(`docs/design`)에 넣는다.
4. 화면을 고쳐서 다시 내보내면 **같은 이름으로 덮어쓴다.** 어떤 이유로 바꿨는지는 `docs/PROGRESS.md`에 한 줄 남긴다.
5. 시안에서 새로 정해진 값(상단·하단 바 높이, 체크박스 크기 등)은 `tokens.md`의 `TODO`를 채운다.
6. Figma Make 프로젝트 링크는 README의 "링크" 절에 적는다(비공개 링크면 적지 않는다).

## 4. Claude Code가 화면을 만들 때의 절차

화면 하나를 만들 때마다 아래 순서를 지킨다.

1. 해당 화면의 `docs/SPEC.md` 명세와 `docs/design/SC-xxx.png`, `tokens.md`를 읽는다. 시안이 없으면 SC-210 시안과 `tokens.md`를 기준으로 삼는다고 먼저 말한다.
2. 시안에서 읽은 내용을 짧게 정리해 보고한다: 배치, 사용한 컴포넌트, 시안과 SPEC 사이에서 다른 점. 다른 점이 있으면 **임의로 고르지 말고 묻는다.**
3. 색, 글자 크기, 모서리, 간격, 버튼 높이는 `tokens.md` 값만 쓴다. 코드에 값을 직접 쓰지 않고 테마(Color, Typography, Shape 등)에 한 번 정의해서 가져다 쓴다.
4. 반복되는 모양(상단 바, 하단 바, 큰 버튼, 체크 항목, 카드, 상태 배지, 스위치)은 공통 컴포넌트로 한 번만 만들고 재사용한다. 화면마다 따로 만들지 않는다.
5. 구현 후 빌드하고 에뮬레이터에서 확인한다. 시안과 다른 곳을 목록으로 보고한다(어긋남이 없으면 "차이 없음").
6. 시안을 이미지 통째로 앱에 넣지 않는다. 실제 Compose 요소로 만든다.
7. 시안에 있는 예시 값(82%, 12,345km, 14:32, PC-0001 등)은 가짜 자리 표시다. 실제 값은 SPEC과 SDK 읽기 결과로 채우고, 읽지 못하면 "확인 불가"를 보여 준다.

## 5. 시안과 SPEC이 충돌할 때

| 종류 | 따르는 문서 |
|---|---|
| 문구, 체크 항목, 동작, 이동 | `SPEC.md` |
| 배치, 색, 글자 크기, 간격, 아이콘 모양 | 시안 PNG, `STYLE-GUIDE.png`, `tokens.md` |
| 둘이 서로 다른 문구 | 멈추고 사용자에게 묻는다 |

시안을 고치거나 SPEC을 고치는 결정은 사용자가 한다. Claude Code는 어느 한쪽을 임의로 고치지 않는다.

### 알려진 불일치 (시안이 나오면 확인할 것)

시안을 만들 때 쓴 프롬프트와 SPEC의 문구가 아래처럼 다르다. 시안이 나온 뒤 사용자가 한쪽으로 정하고 이 표를 지운다.

| 화면 | SPEC | 시안 프롬프트 |
|---|---|---|
| SC-200 | [네, 세웠어요] [아직이에요], 질문 "안전한 곳에 차를 세우셨나요?" | [멈췄어요] [아직 움직이고 있어요], 질문 "차가 완전히 멈췄나요?" |
| SC-210 | 체크 항목 4개 (동승자 이동 포함) | 3개 |
| SC-230 | 촬영 체크 5개 | 3개, 음성 메모 카드 포함 |

## 6. 크기와 단위

- 에뮬레이터 앱 영역은 1682×1210dp, 화면 밀도 160이라 **시안의 1px = 코드의 1dp**다.
- 글자는 sp로 쓰되 시안의 px 값을 그대로 옮긴다.
- 화면 가장자리 안전 여백은 48이다. 계기판 영역과 하단 공조 바는 앱 영역 밖이므로 그리지 않는다.
- 화면이 어긋나면 임의로 값을 바꾸지 말고, 실제 크기를 다시 측정해 사용자에게 알린다.

## 7. 디자인이 바뀔 때

- 시안 PNG를 덮어쓰고 `tokens.md`의 값이 바뀌었는지 확인한다.
- Claude Code에게는 "SC-xxx 시안이 바뀌었어. 이전 구현과 다른 부분만 알려 주고, 그 부분만 고쳐 줘"라고 요청한다. 화면 전체를 다시 만들지 않는다.
- 전체 테마 값(색 등)이 바뀌면 테마 정의 한 곳만 고친다.

## 8. 하지 않는 것

- Figma Make가 만든 React/웹 코드를 Android 프로젝트에 복사하지 않는다.
- 시안의 이미지 파일을 앱 리소스로 그대로 쓰지 않는다(아이콘이 필요하면 따로 이야기한다).
- 시안에 없는 화면이나 기능을 디자인 핑계로 추가하지 않는다.
- `tokens.md`에 없는 색, 28보다 작은 글자, 96보다 낮은 터치 영역을 쓰지 않는다.
