# Pit Crew

> 사고 직후 정차부터 마무리까지 안내하는 Pleos Connect 차량용 앱

사고가 났을 때 당황하기 쉬운 초보 운전자를 포함한 모든 운전자가, 정차 확인 → 안전 확보 → 현장 기록 → 마무리까지 화면의 짧은 안내를 따라 할 수 있게 돕습니다. 법적 판단이나 과실 판단은 하지 않으며, 모든 안내는 **참고용**입니다(법률·의료 조언 아님).

## 1. 실행 방법

1. Android Studio에서 이 폴더(`pit-crew`)를 엽니다.
2. Gradle JDK를 **JDK 21**로 설정합니다. (Settings > Build > Gradle > Gradle JDK)
3. Gradle Sync 후 Pleos Connect Emulator(아래 3번)를 켭니다.
4. 실행 대상으로 에뮬레이터를 고르고 ▶ Run 합니다.
5. 홈(SC-100)에서 시작 버튼을 눌러 사고 모드를 진행합니다.

> 실차 시연은 지원되지 않아 에뮬레이터 기준으로 개발·검증했습니다.

## 4. SDK 버전

| SDK | 버전 | 용도 |
|---|---|---|
| Pleos Vehicle SDK | 2.3.2 (Vehicle Service 2.3.22) | 차량 값 읽기 (읽기 전용) |
| FusedLocation | 1.1.3 | 사고 위치 기록 (사용자 허용 시) |
| NaviHelper | 3.0.5 | 길안내 요청 (사용자 선택 시) |
| TextToSpeech | 3.3.1 | 음성 안내 (`ON_DEVICE` 모드) |
| SpeechToText | 3.3.1 | 음성 메모 (`ON_DEVICE` 모드) |

외부 API(키 불필요, 3초 안에 응답 없으면 "확인 불가"): OpenStreetMap Nominatim(주소 변환), Open-Meteo(날씨).

**지도 데이터 출처:** 주소는 © OpenStreetMap contributors의 데이터이며 ODbL 1.0 라이선스입니다(https://www.openstreetmap.org/copyright). 주소가 보이는 화면마다 "© OpenStreetMap contributors"를 표시합니다. 공용 Nominatim 서버는 사용 정책(초당 1회 이하, 앱을 식별하는 User-Agent, 출처 표기)을 지켜 시연용 소규모로만 씁니다. 앱은 사고 모드를 시작할 때 세션당 1회만 호출하고 실패해도 다시 시도하지 않습니다. User-Agent는 앱 이름과 버전뿐입니다. 정책이 요구하는 "운영 측 요청 시 앱 업데이트 없이 서비스 전환"은 지원하지 않습니다(알려진 한계).
보험사 연계는 **시연용 가상 보험사(목업)** 이며 화면에도 그렇게 표시합니다.

## 5. 가상 값 안내

- 에뮬레이터가 주는 차량 값은 실제 차량 값이 아닙니다.
- 읽을 수 없거나 실패한 값은 앱이 종료되지 않고 **"확인 불가"** 로 표시합니다.
- 정차 여부는 속도·기어를 읽지 않고 **사용자 확인(SC-200)** 으로 판단합니다.

## 6. 지원하지 않는 항목

- 차량 제어(set 호출, CONTROL_* 권한): 사용하지 않음. 차량 권한은 읽기 권한만 선언합니다. 그 밖에 선언한 권한은 음성 안내 서비스 권한(`pleos.car.permission.TTS_SERVICE`, **차량 권한이 아닌 일반 권한**, 설치 때 자동 허용), 음성 메모 서비스 권한(`pleos.car.permission.STT_SERVICE`, **차량 권한이 아닌 일반 권한**, 설치 때 자동 허용), 위치 읽기(`pleos.car.permission.FUSED_LOCATION`, 사용자가 SC-205에서 켠 때 시스템 권한 창으로 허용)와 **차량 권한이 아닌 일반 네트워크 권한**(`android.permission.INTERNET`, 주소 조회용)입니다.
- 사고 자동 감지, 에어백 상태, 문 잠김, 차대번호(VIN), 비상등 자동 확인, 타이어 값
- 법적 판단·과실 판단·의료 조언
- 상대방 정보, 사진, 차대번호의 저장·전송
- 차량 화면에서의 타이핑 입력
- 실제 보험사 연동 (시연용 목업만 제공)
- 날씨(Open-Meteo 무료 API)는 비상업 용도로만 쓸 수 있습니다. **상업적 사용 시 유료 요금제가 필요합니다.**
- 날씨를 조회하면 Open-Meteo 서버 로그에 좌표가 **최대 90일** 남을 수 있습니다(공식 약관 기준, 앱은 좌표를 소수점 2자리로 반올림해 보냅니다).

## 7. 개인정보 원칙

- 위치·음성은 SC-205에서 사용자가 허용한 경우에만 사용합니다. 꺼져 있어도 사고 모드는 끝까지 진행됩니다.
- 기록 저장(SC-270)과 외부 전송은 사용자가 켠 경우에만 이루어집니다. 저장 기록에는 좌표, 부상 응답, 상대방 정보, 사진, 차대번호가 없습니다. 보험사 전송(목업)은 사용자가 [보내기]를 눌러야 하며, 항목별 선택과 전송 로그를 보여 줍니다.
- 키, 토큰, 비밀번호, 개인 이메일을 코드·로그·문서에 넣지 않습니다.

> 현재(Phase 0): 앱을 켜면 임시 자리표시 화면이 보입니다. 디버그 빌드에서만 [개발자 도구](읽기 전용 차량 API 탐색기)가 열리며, 제어(set) 기능은 코드에서 제거했고 탐색기도 check/get/is/register/unregister 함수만 호출합니다.

> 날씨(Phase 11-A): 위치와 네트워크 스위치를 모두 켠 경우에만, 사고 모드 시작 때 위치를 읽은 뒤 주소 조회와 함께(동시에) Open-Meteo(키 필요 없음)에 좌표를 소수점 2자리(약 1km)로 반올림해 한 번 보내 현재 온도와 날씨 코드를 받고, SC-250 오른쪽 아래 "날씨" 카드에 "맑음 18°C"처럼 보여 줍니다. 날씨 코드는 Open-Meteo 문서의 WMO 코드 표에 있는 것만 한국어로 바꾸고 표에 없는 코드는 "확인 불가"입니다. HTTPS만 쓰고 캐시와 재시도가 없으며 3초 안에 응답이 없으면 회색 "확인 불가"로 표시하고 사고 모드는 계속됩니다. 위치나 네트워크를 끄면 날씨 카드가 보이지 않습니다. 좌표는 호출에만 쓰고 세션, 로그, 화면에 남기지 않습니다. 사고 기록에는 조회에 성공했을 때만 날씨 상태, 조건, 온도가 들어갑니다(저장 형식 버전 2, 좌표 없음). 출처: Weather data by [Open-Meteo.com](https://open-meteo.com/) (CC BY 4.0, 화면에도 "Weather data by Open-Meteo.com"를 날씨 값 옆에 보여 줍니다).

> 음성 메모(Phase 11-B): SC-205에서 음성을 켠 경우에만, SC-230 오른쪽 "말로 메모 남기기" 카드의 [말하기]를 누르면 SpeechToText(`Mode.ON_DEVICE`, 한국어)로 한 번 듣습니다. 말하기 전에 "상대방 이름·번호·연락처는 말하지 마세요"를 보여 주고, 듣는 중에는 [멈추기]가 보이며(최대 30초), 인식 결과(최대 100자)를 확인한 뒤 [저장] 또는 [다시 말하기]를 고릅니다. **메모는 사고 모드 세션 메모리에만 두고 디스크에 쓰지 않으며 사고 기록(SC-270 저장)에도 넣지 않습니다**(홈으로 가면 사라집니다). 오디오는 받지도 저장하지도 않고(SDK가 돌려주는 텍스트만 사용), 로그에는 글자 수만 남깁니다. 화면을 옮기거나 앱이 가려지거나 사고 모드가 끝나면 듣기를 멈추고 SDK를 해제합니다. 초기화 실패 등 사용할 수 없으면 카드가 회색으로 바뀌고 사고 모드는 계속됩니다. **이 PC에는 마이크가 없어 실제 한국어 인식은 확인하지 못했습니다**(호출 흐름, 해제, 화면 상태는 에뮬레이터에서 확인).

> 종료와 기록 저장(Phase 10): SC-260 다음에 SC-270. [기록 저장]은 사용자가 누를 때만 사고 시각, 위치·주소(위치 상태와, 조회에 성공했으면 주소와 출처 표기. **좌표는 저장하지 않습니다**), 차량 상태(문·창문 영역별 값, 배터리, 주행 거리, 방향지시등, 읽은 시각), 안내 이행(체크한 항목)을 이 기기의 앱 내부 저장소(백업에서 제외되는 `noBackupFilesDir`, JSON 한 파일)에 **최근 1건만** 저장합니다. 새로 저장하면 이전 기록이 바뀝니다. 부상 응답, 상대방 정보, 사진, 차대번호는 저장하지 않습니다. 위치를 껐거나 읽지 못했거나 주소 조회에 실패하면 기록에 그 상태만 남고 사고 모드는 정상 동작합니다. 저장하지 못하면 "저장하지 못했어요"가 보이고 앱은 계속 동작합니다. [저장하지 않고 종료]는 아무것도 저장하지 않고 홈으로 갑니다. 저장 기록을 지우는 사용자 화면(SC-520)은 아직 없고, 디버그 빌드의 [개발자 도구] "저장 기록 삭제"로만 지울 수 있습니다(제출 전 정리 예정).

> 소리로 듣기(Phase 9): SC-205에서 음성을 켜면 SC-210, 220, 221, 230, 240 상단 바의 [소리로 듣기]로 그 화면의 안내 문구를 읽어 줍니다(TextToSpeech `ON_DEVICE`, 한국어). 자동 재생은 없고 누를 때만 읽으며, 읽는 중에는 [멈추기]가 됩니다. 화면을 옮기거나 앱이 화면에서 사라지면 멈추고, 사고 모드가 끝나 홈에 도착하면 해제합니다. 주소와 좌표는 읽지 않습니다. 초기화 실패나 재생 오류는 "소리 안내 불가"로 보이고 사고 모드는 계속됩니다. 에뮬레이터에서는 이벤트와 오디오 상태로만 확인했고 실제 소리와 발음은 확인하지 못했습니다.

> 주소 변환(Phase 8): 위치와 네트워크 스위치를 모두 켠 경우에만, 사고 모드 시작 때 위치를 읽은 뒤 좌표(소수점 4자리 반올림)를 OpenStreetMap Nominatim에 보내 주소 한 줄(시/도 구 도로명 번호)을 받아 SC-221, SC-250, SC-260에 보여 줍니다. 좌표는 호출에만 쓰고 세션에는 주소 문자열과 상태만 메모리로 보관하며 저장·로그·화면 표시를 하지 않습니다. 상호(name)는 버립니다. 네트워크 스위치를 켜면 SC-205에 "켜면 사고 위치를 주소·날씨 조회 서버로 보내요" 안내가 보입니다. 3초 안에 응답이 없거나 네트워크가 끊기면 "주소 확인 불가"로 표시하고 사고 모드는 계속됩니다. 상대방 정보, 사진, 차대번호와는 섞지 않습니다.

> 권한·동의와 위치(Phase 7): 사고 모드에 처음 들어갈 때 한 번 SC-205에서 위치, 음성, 네트워크 스위치(기본 꺼짐)를 고릅니다. 선택은 앱을 껐다 켜도 유지되며 저장하는 값은 켜짐/꺼짐뿐입니다. 위치를 켜면 시스템 권한 창이 뜨고, 허용한 경우에만 사고 모드 시작 때 마지막 위치를 한 번 읽어 세션 메모리에 둡니다(저장·전송·화면 표시 없이 "위치 확인됨" 같은 상태만 보여 줍니다, 주소 변환은 이후 단계). 읽지 못하면 "확인 불가"로 표시하고, 모두 꺼도 사고 모드는 끝까지 진행됩니다. 음성·네트워크 스위치는 값만 저장합니다(해당 기능은 이후 단계). 디버그 빌드의 [개발자 도구]에만 [동의 초기화] 버튼이 있습니다. 시험할 때 에뮬레이터 앱은 사용자 10으로 돌아 `adb shell pm grant --user 10 …`처럼 사용자를 지정해야 합니다.

> 출발 전 점검·연동 상태(Phase 6): 홈의 [출발 전 점검](SC-300)은 들어올 때와 [다시 확인]을 누를 때 문(앞쪽 덮개·뒤쪽 포함), 창문, 배터리, 방향지시등을 읽어 "이상 없음" 또는 "확인 필요 N건"으로 보여 줍니다(열림 기준은 값이 0보다 큰 것, 방향지시등이 켜져 있으면 확인 필요, 읽지 못한 항목은 "확인 불가"이며 이상으로 세지 않음, 배터리는 값만 표시). 사고 모드 세션과 무관하며 읽기 전용입니다. [차량 연동 상태](SC-400)는 문, 창문, 배터리, 주행 거리, 방향지시등의 지원 여부("읽을 수 있어요" / "이 차량에서는 지원하지 않아요" / "확인하지 못했어요")와 마지막 확인 시각을 보여 주고, [다시 확인]은 지원 여부를 다시 확인합니다(홈의 "차량 정보 5개 중 N개" 문구도 같은 값을 씁니다).

> 접수 요약(Phase 5): SC-250 다음에 SC-260 접수 요약. 보험사에 말할 순서(무슨 일, 사고 장소, 다친 사람, 차량 상태, 상대방 확인)와 기록 시각, 체크 현황(확인함/확인 안 함)을 보여 줍니다. 화면 표시만 하며 저장하거나 외부로 전송하지 않습니다. 위치, 사진, 상대방 정보, 차대번호는 표시하지 않습니다.

> 차량 상태(Phase 4): SC-200 [네, 세웠어요]에서 문, 창문, 배터리, 주행 거리, 방향지시등을 한 번 읽어 사고 모드 세션에 메모리로만 보관하고, SC-250에서 보여 줍니다([다시 읽기]로 갱신). 읽기 전용(get 호출만, 리스너 없음)이며 읽지 못한 항목은 "확인 불가"로 표시합니다. 값은 에뮬레이터의 가상 값입니다.

> 사고 모드(Phase 3-c): SC-230 현장 기록 안내(휴대폰으로 촬영할 항목 체크 5개, 앱은 사진을 찍거나 저장하지 않으며 카메라 기능이 없음, 음성 메모는 아직 비활성)와 SC-240 상대방 정보 확인(체크 3개, 입력창 없음, 상대방 정보는 저장하지 않음). 체크 여부는 사고 모드 세션에만 메모리로 보관합니다.

> 사고 모드(Phase 3-b): SC-210 다음에 SC-220 부상 확인(없어요/있어요/잘 모르겠어요, 응답은 세션에 메모리로만 보관). 있어요·잘 모르겠어요는 SC-221 긴급 안내(119·112 안내만, 앱은 전화를 걸지 않음)를 거쳐 SC-230으로 갑니다. SC-221 문구는 초안입니다.

> 사고 모드(Phase 3-a): 홈에서 [사고가 났어요] → SC-200 정차 확인(사용자 확인으로만 판단, 속도·기어를 읽지 않음) → SC-210 안전 확보(체크 4개, 체크 상태는 사고 모드 세션에 메모리로만 보관하고 홈에 돌아오면 버림). 나머지 단계는 자리표시 화면입니다.

> 홈(Phase 2): 앱을 켜면 SC-000이 Vehicle SDK를 초기화하고 문·창문·배터리·주행 거리·방향지시등의 지원 여부(읽기 가능/미지원/확인 실패)만 확인한 뒤 SC-100 홈으로 이동합니다. 초기화가 실패해도 홈으로 가고 차량 연동만 끕니다. 값 읽기는 하지 않습니다. 시작 때 시간 안(기능별 3초)에 응답하지 못한 기능(UNKNOWN)은 홈으로 간 직후 한 번만 다시 확인하고, 사고 모드 시작(SC-200)과 출발 전 점검(SC-300)의 읽기 전에도 아직 UNKNOWN인 기능만 다시 확인합니다(읽기 전용, 한 번에 하나씩, 실패하면 "확인 불가"). 실제 차량에서의 동작은 확인하지 못했습니다.

> 공통 틀(Phase 1): 테마 `ui/theme/pitcrew/`, 공통 컴포넌트 `ui/components/`(상단·하단 바, 단계 막대, 버튼, 체크 항목, 카드, 상태 배지), 화면 이동 틀 `ui/nav/`. 디버그 빌드의 [개발자 도구]에서 컴포넌트 미리보기와 화면 이동 틀을 볼 수 있습니다(릴리스에는 없음).

> 화면 이름과 세부 동작은 개발이 진행되는 대로 이 표에 갱신합니다. 기준 문서: 「Pit Crew 기획서 및 MVP 상세 정의서」.

### SDK별 동작

| SDK | 호출 순서 | 해제 |
|---|---|---|
| FusedLocation | `isSupported()` → `initialize()` → `getLastKnownLocation()` (사고 모드 시작 시 1회) | `release()` |
| NaviHelper | `initialize(onConnected, onFailed)` → 연결 후 리스너 등록 → `requestRoute()` (사용자 선택 시) | `removeListener()` → `release()` |
| TextToSpeech | `Mode.ON_DEVICE`로 생성 → `initialize()` → `addEventListener()` → `speak()` | `stop()` → `removeEventListener()` → `release()` |
| SpeechToText | `Mode.ON_DEVICE`로 생성 → `initialize()` → `addListener()` → `request()` | `stop()` → `removeListener()` → `release()` |

공통 규칙: capability 확인 후 읽기, 모든 SDK 호출은 예외 처리, 리스너는 한 번만 등록하고 화면을 떠날 때 해제.

## 10. 개발 방식

기획과 검증, 구조 설계는 개발자가 직접 하고, 코드 작성에는 생성형 AI(Claude Code)를 보조 도구로 사용했습니다. 모든 코드는 화면·SDK 단위로 나누어 만들고 빌드와 에뮬레이터 확인 후 다음 단계로 넘어갔으며, 구조와 로직은 개발자가 설명할 수 있도록 위 "구조" 절에 계속 기록합니다.
